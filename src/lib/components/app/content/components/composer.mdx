## Choose an input

`ComposerInput` is the input surface in either case. By default it renders a contenteditable div; give it an accessible name:

```svelte
<ComposerInput aria-label="Message" />
```

For a **plain-text message**, render a native textarea with `as="textarea"`:

```svelte
<ComposerInput as="textarea" aria-label="Message" placeholder="Write a message…" />
```

Both use the same composition and draft API. `Composer` manages an empty draft by default. Add `triggers` and the popup parts for mentions or actions; these require the default contenteditable input. Use a textarea when the message should remain plain text. Put `value`, `defaultValue`, and `onValueChange` on `Composer`, rather than on the input.

## Anatomy

`Composer` provides the form, editing context, and visual frame. Clicking empty space inside its border focuses the input. `ComposerInput` defaults to contenteditable and contains a ScrollArea. The action row stays outside the scrolling draft.

```svelte
<script lang="ts">
  import ArrowUp from '@lucide/svelte/icons/arrow-up';
  import {
    Composer,
    ComposerActionGroup,
    ComposerActions,
    ComposerInput,
    ComposerSubmit
  } from '#lib/components/ui/composer';
</script>

<Composer onSubmit={handleSend}>
  <ComposerInput aria-label="Message" placeholder="Write a message…" />
  <ComposerActions>
    <ComposerActionGroup><!-- Optional leading buttons --></ComposerActionGroup>
    <ComposerActionGroup align="end">
      <ComposerSubmit aria-label="Send message" size="icon">
        <ArrowUp aria-hidden="true" />
      </ComposerSubmit>
    </ComposerActionGroup>
  </ComposerActions>
</Composer>
```

## Usage

`Composer` submits on Enter and inserts a line break on Shift+Enter by default. `onSubmit` always receives a structured draft, for either input. Use `getComposerText` when your application needs a string. The submit button automatically disables for empty drafts.

```svelte
<script lang="ts">
  import ArrowUp from '@lucide/svelte/icons/arrow-up';
  import {
    Composer,
    ComposerActionGroup,
    ComposerActions,
    ComposerInput,
    ComposerSubmit,
    type ComposerValue,
    getComposerText
  } from '#lib/components/ui/composer';

  let { onSend }: { onSend: (message: string) => void } = $props();

  let value = $state<ComposerValue>([]);
</script>

<Composer
  bind:value
  onSubmit={(draft) => {
    onSend(getComposerText(draft));
    value = [];
  }}
>
  <ComposerInput as="textarea" aria-label="Message" placeholder="Write a message…" />
  <ComposerActions>
    <ComposerActionGroup align="end">
      <ComposerSubmit aria-label="Send message" size="icon">
        <ArrowUp aria-hidden="true" />
      </ComposerSubmit>
    </ComposerActionGroup>
  </ComposerActions>
</Composer>
```

Omit `value` for an uncontrolled draft. Submission does not clear the message automatically. `value` is bindable; use `onValueChange` to observe changes and their reason, and debounce fetching or saving separately.

### Submission and custom controls

Set `submitDisabled` on `Composer` while sending or whenever your application cannot accept the message. It blocks both Enter and the submit button while leaving the draft editable. Use `disabled` to disable the input as well, or `readOnly` to keep text selectable without allowing edits or submission.

```svelte
<Composer submitDisabled={sending} allowEmpty={attachments.length > 0} onSubmit={handleSend}>
  <!-- Input and actions -->
</Composer>
```

`allowEmpty` lets you send an attachment without text. `ComposerSubmit` renders a coss `Button`, so it accepts `variant`, `size`, and `loading`; choose its label and icon as children. Its own `disabled` prop only controls that button. Use `submitDisabled` on `Composer` for a rule that must also apply to Enter.

`name` adds the canonical message text to the form's `FormData` through a hidden input, for either input. `Composer` always renders a `<form>` and runs native constraint validation before its `onSubmit` callback; don't nest it inside another form. Required-field validation is available on a textarea; contenteditable does not support native `required` validation.

Resetting the form restores `defaultValue` (or an empty draft), and `onValueChange` receives `reason: "reset"`. For custom controls within Composer, `useComposerContext()` exposes the draft, `canSubmit`, `submit()`, `insertTrigger()`, and `reset()`. The same editor state is also passed to the `Composer` children snippet.

### Input size

Set row limits with CSS variables on `Composer`. They apply to both the default contenteditable input and a textarea. By default, the input starts at one row below `md` and two rows from `md` upward. It grows to four rows below `md` and eight rows from `md` upward. Longer drafts scroll while the controls stay visible. The maximum also stays within half the viewport height. Add attachment, microphone, or other buttons inside `ComposerActions`.

Use responsive classes to change the limits at each breakpoint:

```svelte
<Composer class="[--composer-min-rows:2] [--composer-max-rows:3] md:[--composer-min-rows:3] md:[--composer-max-rows:6]">
  <ComposerInput as="textarea" aria-label="Message" />
  <ComposerActions><!-- Buttons --></ComposerActions>
</Composer>
```

Here the input shows two to three rows below `md` and three to six rows from `md` upward. Keep the minimum at or below the maximum at each breakpoint. Set these variables on `Composer` so both the input and its scroll area inherit them.

### Controls beside a short message

Set `layout="adaptive"` to place controls beside a one-line draft. When text wraps or you add a line break, the input takes the full width and the controls move below it. Both layouts use the same composition: `ComposerInput` followed by `ComposerActions`, with action groups aligned to `start` and `end`. Only the `layout` prop changes.

The adaptive layout starts at one visible row; setting `--composer-min-rows` above one keeps the controls below. Keyboard focus follows the same order in both layouts: input, leading actions, then trailing actions.

## Mentions and actions

The same `Composer` composition supports mentions and slash actions.

<ComponentPreview name="p-composer-1" />

To extend the anatomy above, pass `{triggers}` to `Composer` and insert these parts immediately after `ComposerInput`. The demo's Code tab shows the complete composition.

```svelte
<ComposerPopup>
  <ComposerList>
    {#snippet children(item)}
      <ComposerItem value={item}>
        {item.label}
      </ComposerItem>
    {/snippet}
  </ComposerList>
</ComposerPopup>
```

Configure only the triggers you need. Queries can contain spaces: `@sam r` finds Sam Rivera. A space immediately after the trigger closes the suggestions. By default, selecting an item inserts a token into the draft; it does not send the message or execute an action. Supply `onAction` to handle items with `type: "action"` as commands: Composer removes the active query and calls your handler without inserting a token or submitting. Your application owns execution.

To open a trigger from a button inside `ComposerActions`, call `useComposerContext().insertTrigger('@')` or `insertTrigger('/')`. The trigger is inserted at the caret and opens the same suggestions as typing it.

```ts
const triggers: ComposerTrigger[] = [
  { character: '@', items: [{ id: 'sam', label: 'Sam Rivera' }] },
  { character: '/', items: [{ id: 'summarize', label: 'Summarize', type: 'action' }] }
];
```

Omit `triggers` and the popup parts for plain contenteditable text. Use `bind:value` for a controlled draft, or `defaultValue` for an uncontrolled draft. Submission does not clear the structured draft automatically.

### Token appearance

By default, selected mentions and actions appear as `text-primary font-medium` text with their trigger (`@Sam Rivera` or `/Summarize`). To change their appearance, pass a `renderToken` snippet to `ComposerInput`. This example uses the same people, teams, and actions as the one above, but gives them rounded chips with different icons.

<ComponentPreview name="p-composer-6" />

The selected item's `kind` reaches `renderToken`, so a person and a team selected from the same `@` menu can use different icons or styles. The structured draft keeps `type`, `kind`, `id`, `label`, `trigger`, and optional `data` and `text`; `getComposerText(value)` returns the explicit `text` or defaults to text such as `@Sam Rivera`, even when a chip hides the trigger visually. A native textarea remains plain text and does not render tokens.

### Custom filtering

The default filter ignores case and accents. Set a trigger's `filter` to customize matching. `useComposerFilter` exposes ShardsUI's `contains`, `startsWith`, and `endsWith` helpers.

### Emoji

Give an item `type: 'text'` to replace the query with its `text` as ordinary characters, instead of inserting a token. This demo uses it for Slack-style emoji: typing `:thu` suggests 👍, and selecting it replaces `:thu` with the emoji and a space. The emoji is plain draft text, so backspace, copy, undo, and `getComposerText` treat it like any typed character.

<ComponentPreview name="p-composer-12" />

The Composer doesn't ship emoji data. The demo uses a curated list of about 140 common emoji (`#lib/data/emoji.ts`, installed with the particle), each with an `emoji`, a `shortcode`, and `keywords`, and ranks matches in `onQueryChange`: shortcode prefixes first, then keyword prefixes, then substrings, up to eight results. Queries shorter than two characters return no items, so the popup stays closed. Because `:` opens only after a space or at the start of the draft, times such as `10:30` and URLs such as `https://` never open it.

```svelte
<script lang="ts">
  import { searchEmoji } from '#lib/data/emoji.js';

  let emoji = $state<ComposerItemValue[]>([]);
</script>

<Composer
  onQueryChange={(query) => {
    emoji = query?.character === ':' ? searchEmoji(query.text) : [];
  }}
  triggers={[{ character: ':', items: emoji, filter: null }]}
>
```

Each `searchEmoji` result is `{ id: 'thumbsup', label: 'thumbsup', text: '👍', type: 'text' }`, so the list can show `item.text` beside `:{item.label}:`.

### Async results

Fetch results in response to `onQueryChange`. Use `filter: null` for prefiltered results and `itemsFor` to identify their query text. For caret-sensitive results, return the opaque `ComposerQuery.key` as the trigger's `queryKey`; results from a different query position cannot be selected even when the text matches. Do not persist or parse the key.

A completed query with no matches closes the popup by default. Set `showEmpty: true` to keep it open and render an empty state with `ComposerStatus`. `maxQueryLength` optionally limits the query text after the trigger. When a popup has no selectable results, Enter is blocked by default; `submitOnEmptySuggestions` lets Enter follow the normal submission policy, including during loading or error states.

### Keyboard shortcuts

While suggestions are open, ↑ and ↓ navigate, Enter selects, Escape dismisses, and Tab moves focus normally. Shift+Enter dismisses suggestions and inserts a line break. Otherwise, Enter submits and Shift+Enter inserts a line break in the contenteditable input or textarea. Set `submitOnEnter="desktop"` to submit only with a fine pointer, or `"never"` to let Enter insert a line break.

## In a drawer

Bottom drawers automatically keep the input above the software keyboard. Place the composer after the scrolling `DrawerPanel` so it stays visible. Set the drawer height in your composition; Drawer handles keyboard and safe-area spacing automatically. Leave the Composer free to shrink in the drawer: its input scrolls in the remaining space while the action row stays visible.

### ComposerInput

The editable input with an internal coss ScrollArea. It connects to its parent Composer automatically. Give it an accessible name with `aria-label` or `aria-labelledby`.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `as` | `"div" \| "textarea"` | `"div"` | Renders a contenteditable div, or a native textarea for plain text |
| `placeholder` | `string` | — | Placeholder for the input |
| `renderToken` | `Snippet<[ComposerTokenPart]>` | — | Renders each selected token in the contenteditable input; defaults to `ComposerToken` |
| `class` | `string` | — | Additional classes on the editable element |
| `ref` | `HTMLElement \| null` | — | Bindable reference to the editable element |
| `...props` | Element attributes | — | Other attributes forwarded to the editable element |

Set the following CSS variables on `Composer` using `class`. Row counts follow the input's actual line height, including the change from `text-base` below `md` to `text-sm` on larger screens. Vertical padding is included automatically. A textarea does not need a native `rows` attribute.

| CSS variable | Default | Description |
| --- | --- | --- |
| `--composer-min-rows` | `1` below `md`, `2` from `md`; `1` in adaptive layout | Minimum visible text rows |
| `--composer-max-rows` | `4` below `md`, `8` from `md` | Maximum visible text rows before scrolling |
| `--composer-padding` | `--spacing(2)` | Top content spacing and bottom control spacing; the top spacing scrolls with the text |
| `--composer-max-height` | Calculated from maximum rows and padding | Optional CSS height that replaces the row-based maximum |

The maximum height is also capped at `50dvh`. The four-row mobile default leaves more room for surrounding content, such as a conversation inside a drawer.

The default div has multiline textbox semantics. A textarea uses the same parent-owned draft and submission policy. Use one `ComposerInput` per `Composer`.

## Drafts and triggers

### Draft and trigger types

```ts
type ComposerValue = readonly ComposerPart[];

type ComposerPart =
  | { type: 'text'; text: string }
  | { type: 'mention' | 'action'; id: string; label: string; trigger: string; kind?: string; data?: string; text?: string };

type ComposerTokenPart = Exclude<ComposerPart, { type: 'text' }>;

type ComposerItemValue = {
  id: string;
  label: string;
  disabled?: boolean;
  description?: string;
  type?: 'mention' | 'action' | 'text';
  kind?: string;
  data?: string;
  text?: string;
};

type ComposerQuery = { character: string; text: string; key: string };
```

Item IDs must be unique within each trigger. Set `disabled: true` on an item to skip it during keyboard navigation and prevent selection. `type` defaults to `"mention"`; set `"action"` for slash actions, or `"text"` to insert the item's `text` (or its `label`) as plain characters instead of a token. Use `kind` for your own categories, such as `"person"` and `"team"`, even when both come from `@`. The selected part retains `kind`. `getComposerText(value)` uses a token's optional `text` field, or falls back to its trigger and label. Optional `data` is an opaque string preserved through editing, undo/redo, and supported structured copy/paste; the editor never interprets it as HTML. Keep domain validation and authorization in your application.

`ComposerTrigger` configures one source:

| Field | Type | Default | Description |
| --- | --- | --- | --- |
| `character` | `string` | required | Trigger, such as `"@"` or `"/"` |
| `items` | `readonly ComposerItemValue[]` | required | Candidate results |
| `filter` | `((item, query) => boolean) \| null` | label contains query | Custom matching; `null` uses prefiltered results |
| `itemsFor` | `string` | — | Query the async items belong to |
| `queryKey` | `string` | — | Opaque query identity returned by `onQueryChange`; mismatched results cannot be selected |
| `showEmpty` | `boolean` | `false` | Keeps the popup open when there are no ready matches |
| `maxQueryLength` | `number` | Unlimited | Maximum query text length after the trigger |
| `status` | `"ready" \| "loading" \| "error"` | `"ready"` | Loading/error feedback keeps the popup open; zero ready matches hide it unless `showEmpty` is enabled |

### Draft lifecycle

Copying or cutting includes the token's `text`, or its trigger and label by default, in plain text. It also writes `application/x-coss-composer` data so compatible composers can preserve tokens and metadata. Structured paste validates the document shape and accepts at most 1,000 parts and 100,000 serialized characters; unsupported or invalid structured data falls back to plain text. External text, HTML, and dropped text do not acquire mention IDs. Clipboard metadata is untrusted input and never grants access to application records.

Contenteditable edits have a local undo history, including token insertion, paste, and cut. Replacing the draft externally or resetting it starts a new history. Selection is preserved and clamped to the updated draft. If an external value changes during IME composition, it is applied after composition finishes. A native textarea keeps its browser editing history.

`ComposerChangeDetails.reason` is `"input"`, `"selection"` (selecting a suggestion), `"history"` (contenteditable undo/redo), or `"reset"`.

### useComposerContext

Import this function from the same Composer module and call it during initialization of a descendant component to build custom controls. It returns the Composer's editor state, whose getters are reactive.

```svelte
<script lang="ts">
  import { Button } from '#lib/components/ui/button';
  import { useComposerContext } from '#lib/components/ui/composer';

  const composer = useComposerContext();
</script>

<Button type="button" disabled={composer.isEmpty} onclick={() => composer.reset()}>Reset</Button>
```

| Return value | Description |
| --- | --- |
| `value` | Current `ComposerValue` |
| `isEmpty` | Whether the draft contains no text or tokens |
| `canSubmit` | Whether the shared submission policy permits sending |
| `disabled` | Whether the Composer is disabled |
| `readOnly` | Whether editing is read-only |
| `status` | Active trigger's loading state |
| `submit()` | Requests submission, including native validation for the form |
| `insertTrigger(character)` | Inserts a configured trigger at the caret, separating it from surrounding text when needed, then opens its suggestions. Available with the contenteditable input. |
| `reset()` | Restores the initial draft |

Input event handlers you pass to `ComposerInput` run before Composer's handlers. Call `event.preventDefault()` to override a supported keyboard or clipboard action. Keep application business rules on Composer so they apply to both keyboard and pointer submission.
